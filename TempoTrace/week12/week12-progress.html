TempoTrace

BPM 모드에 자동 녹음과 탭 템포를 더해서, 녹음 파일을 따로 옮기지 않고 한 화면에서 연습하고 분석하도록 만든 내용을 보고합니다.
01. 이번 주 목표

남은 기간에 맞춰 범위를 정했다

  • 지난주 계획: 자동 녹음, 탭 템포, 웹 배포(분석까지 브라우저로 이식)
  • 종강까지 약 2주가 남아서, 끝까지 완성할 수 있는 범위로 조정 분석 코드(librosa)를 자바스크립트로 다시 만드는 일은 검증 비용이 커서 이번 학기 범위에서 제외
  • 이번 주 구현 ① 자동 녹음 (BPM 설정 → 카운트 → 메트로놈과 함께 녹음 → 바로 분석)   ② 탭 템포   ③ 웹에 올릴 수 있는 녹음 페이지
  • 유지한 것: 곡 모드와 기존 BPM 모드는 변경 없이 그대로 (11주차와 같은 결과임을 확인)
02. 왜 자동 녹음인가

연습 한 번에 거치던 단계를 줄였다

11주차까지12주차
녹음스마트폰 녹음 앱으로 따로 녹음브라우저에서 바로 녹음
박자메트로놈 앱을 따로 켜야 함BPM을 정하면 메트로놈이 같이 나옴
파일 옮기기파일을 컴퓨터로 옮겨 이름을 맞춤자동으로 저장되고 분석 요청까지 진행
분석 실행터미널에 명령어 입력정지 버튼을 누르면 바로 결과 표시
BPM 입력검색하거나 원곡에서 자동 측정위 방법에 더해 박자에 맞춰 버튼을 눌러서 측정

04. 실행 방법

옵션 하나로 녹음 페이지가 열린다

# 녹음 페이지 열기 (BPM과 눈금 단위를 미리 채워서)
python accuracy_test.py --record --bpm=100 --div=2
# BPM은 페이지에서 정하고 싶을 때
python accuracy_test.py --record
  • 이어폰이나 헤드폰 착용이 필요함 — 스피커로 나온 메트로놈 소리가 마이크에 들어가면 연주가 아닌 클릭까지 분석됨 그래서 안내 문구를 화면 맨 위와 터미널에 모두 표시
  • 녹음 길이는 15초 / 30초 / 60초 / 직접 정지 중에서 선택
  • BPM 모드의 기준값은 곡 모드와 따로 저장된 값을 사용 (리포트에서 바꾸면 모든 기록이 다시 계산됨)
05. 구현 포인트

녹음이 박자 분석에 맞게 만들어지도록 한 부분

문제해결
메트로놈이 흔들리면 연습 기준이 흔들림소리를 "지금" 내지 않고, 브라우저 오디오 시계에 0.15초 앞서 예약하는 방식 — 화면이 잠깐 느려져도 박자는 일정
마이크 처리가 소리 시작을 뭉갬에코 제거, 잡음 억제, 자동 음량 조절을 모두 끄고 녹음
녹음 파일 변환브라우저가 받은 소리를 wav로 직접 만들어서 보냄 → ffmpeg 변환 없이 기존 분석에 바로 사용
카운트 소리가 분석에 섞임4박 카운트가 끝나는 박에 맞춰 녹음을 시작
기기마다 다른 소리 지연BPM 모드는 눈금 위치를 연주에서 자동으로 맞추므로 일정한 지연은 점수에 영향 없음
06. 탭 템포

박자에 맞춰 버튼을 누르면 BPM이 계산된다

  • 방법: 곡을 들으며 버튼을 4번 이상 누르면, 누른 간격의 중앙값으로 BPM을 계산 (최근 8번만 사용) 평균 대신 중앙값을 써서 한 번 삐끗하게 눌러도 결과가 거의 변하지 않게 함  |  2초 넘게 쉬면 처음부터 다시
누른 간격계산된 BPM
600ms × 5번 (= 100 BPM)100
600ms 중 한 번만 700ms100 (튄 한 번이 반영되지 않음)
500ms × 7번 (= 120 BPM)120
220ms × 5번 (= 273 BPM)272 (정수로 반올림하는 과정의 차이)
  • 누른 시각은 사람이 누르는 속도에 영향을 받으므로, 계산된 값은 바로 메트로놈으로 들어보고 맞는지 확인하도록 미리 듣기 버튼을 둠

08. 업로드 안전성

내 컴퓨터로 올라오는 파일을 검사한다

들어온 요청처리
다른 사이트에서 보낸 요청, 다른 주소(Host)로 온 요청거부 (403)
wav가 아닌 형식 / 헤더만 wav인 파일 / 빈 내용거부 (415 / 400 / 422), 분석에 실패한 파일은 저장하지 않음
80MB 초과 (1GB라고 선언한 요청 포함)내용을 읽기 전에 거부 (413)
범위 밖의 BPM(999), 없는 눈금 단위(3), BPM 누락거부 (400)
무음 녹음 (소리 4개 미만)안내만 하고 기록에 남기지 않음 — 0%가 연습 기록에 섞이지 않도록
  • 저장 파일 이름은 서버가 시각으로 정함 — 보낸 쪽이 준 이름을 쓰지 않으므로 다른 폴더에 쓰는 공격이 불가능
  • 위 요청을 모두 보내 본 뒤에도 서버가 꺼지지 않고 정상 응답함을 확인
09. 검증

점검한 내용

  • 기존 기능이 달라지지 않았는지 — 곡 모드 3가지, BPM 모드 3가지, BPM 측정 1가지를 11주차 코드와 같은 입력으로 비교 화면 출력, 분석 결과, 연습 기록, 리포트 데이터가 모두 같음 (기록 시각만 다름)
  • 기존 테스트 재실행 — BPM 테스트, 시작 위치 보정 테스트, 2,000번 반복 실행 모두 통과
  • 녹음 전체 흐름 — 브라우저에서 녹음 시작 → 업로드 → 분석 → 기록 저장 → 리포트 갱신까지 자동 테스트로 확인하고, 실제 기타를 연결해 직접 녹음해서도 결과 화면까지 나오는 것을 확인
  • 메트로놈 — 120 BPM에서 예약된 클릭 9개의 간격이 모두 500ms로 일치 (예약 시각 기준)
  • 입력 오류 — 잘못된 BPM, 너무 짧은 녹음, 마이크 거부, 분석 서버가 없는 경우를 각각 시험
10. 한계

아직 남은 한계

  • 이어폰이 필수: 스피커로 메트로놈을 들으면 클릭 소리가 연주로 분석됨 (페이지와 터미널에 안내)
  • 웹에 올리는 것은 녹음 페이지까지: 웹 배포 상태에서는 메트로놈, 탭 템포, 녹음, wav 저장만 가능하고 분석은 내 컴퓨터의 프로그램에서 함 librosa 분석을 브라우저로 옮기는 작업은 종강 전에 검증까지 끝내기 어려워 제외
  • 메트로놈 소리가 실제로 나오는 시각은 기기와 무선 이어폰의 지연에 따라 달라짐. 일정한 지연은 점수에 영향이 없지만, 지연이 들쭉날쭉하면 영향이 있을 수 있음
  • 실제 기타로 한 번 녹음해 동작은 확인했지만, 여러 곡과 코드 연주에서 기본 기준값(50ms)과 눈금 단위가 알맞은지는 앞으로 확인
  • 템포가 변하는 곡은 BPM이 하나로 잡히지 않아 부정확함 (일정한 템포의 곡 대상)
