연습 기록으로 기준값이 알맞은지 확인하는 검토 모드를 추가하고, 교수님 조언에 따라 방학까지 이어서 완성도를 높이는 로드맵을 정리한 내용을 보고합니다.
01. 이번 주 목표

지난주에 남긴 숙제를 먼저 풀었다

  • 지난주 한계: 기본 기준값(50ms)과 눈금 단위가 실제 기타 연주에 알맞은지 확인하지 못했음
  • 이번 주 구현: 검토 모드(--review) — 쌓인 연습 기록을 기준값별로 다시 채점해서 한 번에 비교 같은 연습을 기준값 25·50·75·100ms로 다시 채점하고, 아무렇게나 쳐도 맞을 확률과 함께 표시
  • 방향 정리: 교수님께서 기간을 늘려 제대로 만들어 보라고 조언해 주셔서, 방학까지 이어서 진행하는 로드맵을 세움 종강 전에 끝낼 범위와 방학에 할 범위를 나눠서 정리 (슬라이드 8번)
  • 유지한 것: 곡 모드, BPM 모드, 녹음 모드는 변경 없이 그대로 (12주차와 같은 결과임을 확인)
02. 왜 검토 모드인가

점수는 기준값에 따라 달라진다

  • 정확도는 "눈금에서 기준값 이내로 친 소리의 비율"이라서, 기준값을 바꾸면 같은 연주도 점수가 달라짐
  • 기준값을 크게 잡을수록 점수는 오르지만, 아무렇게나 쳐도 맞는 확률(우연)도 같이 올라감 예: 100 BPM 8분음표 눈금(간격 300ms)에서 기준값 50ms이면 우연히 맞을 확률 33%, 100ms이면 67%
  • 그래서 "기준값을 몇 ms로 둘까"는 감이 아니라 내 연습 기록을 보고 정해야 함
  • 기록마다 친 소리의 시각이 원본 그대로 저장되어 있어서, 기준값을 바꿔도 녹음 파일 없이 다시 채점 가능 (7주차에 만든 구조를 활용)
03. 검토 모드의 동작

기록 전체를 기준값별로 다시 채점한다

연습 기록 읽기BPM 모드 기록만
→
기준값별 재채점25 · 50 · 75 · 100ms
→
연습별 표최근 20건
→
BPM·단위별 평균템포마다 비교
→
웹 페이지 + CSV그래프로 확인
  • 표에는 우연히 맞을 확률, 눈금 집중도, 박자 흔들림(ms)을 함께 보여줌
  • 기준값이 눈금 간격의 절반을 넘는 칸은 "-"로 비워 둠 — 그 구간은 아무렇게나 쳐도 100%가 되어 점수가 의미 없기 때문 예: 눈금 간격 231ms(130 BPM 8분음표)에서는 115ms까지만 점수를 계산
  • 소리가 눈금에 모이지 않은 연습(집중도 0.5 미만)은 "눈금에 안 모임"으로 표시 — BPM이 틀렸거나 마이크 문제일 수 있음
04. 실행 방법

옵션 하나로 표가 나온다

# 지금까지 쌓인 BPM 모드 연습 기록을 기준값별로 다시 채점 (브라우저가 열림)
python accuracy_test.py --review
  • 음원 파일 없이 저장된 기록만 읽으므로 몇 초 안에 끝남
  • 실행하면 브라우저에 결과 페이지가 자동으로 열림 — BPM·눈금 단위별 그래프(연습별 선, 평균, 우연)와 연습별 표 터미널에도 같은 표가 출력되고, 페이지는 practice_review.html 파일로도 저장됨
  • 녹음 · 결과 리포트 · 기준값 검토를 같은 서버에서 열고, 페이지 위쪽 메뉴로 오가며 사용 녹음 직후 "기준값 검토"를 누르면 방금 기록까지 반영된 최신 비교가 나옴 (끝낼 때는 터미널에서 Ctrl+C)
  • 같은 폴더에 practice_review.csv도 저장됨 — 엑셀에서 열 수 있음 (한글이 깨지지 않는 인코딩)
  • 기록이 없으면 "먼저 --record로 연습해 보라"고 안내하고 끝냄
  • 사용 순서: --record로 여러 번 연습 → --review로 기준값 확인 → 리포트에서 기준값 조정
05. 실행 화면

실제 연습 기록을 다시 채점한 결과 페이지

내 연습 기록으로 열린 --review 결과 페이지 (클릭하면 크게 볼 수 있음)

100 BPM · 8분음표(눈금 간격 300ms) 기록 1건, 평균 흔들림 44.5ms. 25→50ms에서 점수가 가장 크게 뛰므로 박자가 그 근처에서 흔들린다는 뜻입니다. 다만 기록이 1건이라 기본값을 확정하지 않고, 기록을 더 모은 뒤 정합니다.
07. 검증

점검한 내용

  • 다시 채점한 값이 기존 값과 같은지 — 저장된 기준값으로 다시 계산한 정확도가 기록에 저장된 정확도와 시험한 6건 모두 일치
  • 기존 기능이 달라지지 않았는지 — 곡 모드 3가지, BPM 모드 3가지, BPM 측정 1가지를 12주차 코드와 같은 입력으로 비교 화면 출력, 분석 결과, 연습 기록이 모두 같음 (기록 시각만 다름)
  • 녹음 모드 — 녹음 → 분석 → 기록 흐름이 그대로 동작하고, 새로 쌓인 기록을 검토 모드가 바로 읽음
  • 결과 페이지 — 기록이 1건일 때와 6건일 때, 휴대폰 너비에서도 화면이 넘치지 않고 오류 없이 열림
  • 메뉴 이동 — 기록이 없는 상태에서 녹음 → 결과 리포트 → 기준값 검토로 이동하고, 방금 녹음한 기록이 검토 페이지에 바로 반영됨. 파일로 열었을 때는 메뉴가 숨겨져 깨진 링크가 없음
  • 예외 상황 — 기록이 없을 때, BPM이 일부러 틀린 연습(집중도 낮음), 눈금 간격이 좁아 일부 기준값이 무의미한 경우를 각각 시험
08. 로드맵

방학까지 이어서 하는 계획

단계할 일끝났다고 볼 기준
1. 종강 전실제 기타 연습을 여러 번 쌓아 기본 기준값·눈금 단위 확정, README 작성연습 기록으로 정한 기준값이 근거와 함께 문서에 있음
2. 방학 초분석 엔진을 웹으로 이식 (소리 시작 검출과 채점을 자바스크립트로)같은 녹음에서 파이썬과 웹의 결과가 허용 오차 안에서 일치
3. 방학 중설치 없이 웹에서 전체 사용, GitHub Pages 공개, 곡별 BPM 저장, 구간 반복 연습링크만 열면 녹음부터 결과·기록까지 동작
4. 방학 후반밴드부원에게 써 보게 하고 피드백 반영, 포트폴리오 정리다른 사람이 설명 없이 한 번 쓸 수 있음
  • 가장 큰 위험은 2단계: 웹 버전의 소리 검출이 librosa와 다르게 나올 수 있음 → 실제 기타 녹음으로 비교해 오차를 확인하고, 안 맞으면 지금 구조(내 컴퓨터에서 분석)를 유지
09. 한계

아직 남은 한계

  • 기록이 적으면 결론이 약함: 기준값 비교는 연습이 여러 번, 템포가 여러 가지로 쌓여야 믿을 수 있음 (현재는 그 과정을 시작한 단계)
  • 기준값은 자동으로 정해 주지 않음: 표를 보고 사람이 판단하는 구조. 기준이 되는 정답 데이터가 없어서 자동 추천은 근거가 약함
  • 점수의 의미: BPM 모드는 "박자 눈금에 얼마나 붙었나"이며 곡과 같은 리듬으로 쳤는지는 판단하지 않음
  • 웹 공개 상태에서는 아직 분석이 내 컴퓨터의 프로그램에서만 가능 (방학 단계 2~3에서 해결할 과제)
10. 다음 계획

다음 주까지 할 일

  • 연습 기록 쌓기: 템포와 눈금 단위를 바꿔 가며 기타로 여러 번 녹음하고, --review로 기준값 비교
  • 기본값 정하기: 비교 결과를 근거로 BPM 모드의 기본 기준값과 권장 눈금 단위를 정리
