TempoTrace

허용 오차(TOLERANCE) 값을 실시간으로 조정하며 정확도를 확인할 수 있도록 결과 화면을 개선한 과정을 공유합니다.
01. 지난 계획 요약

4주차에 세운 다음 계획

  • 실제 기타 연주를 스마트폰으로 녹음해서 진짜 데이터로 정확도 계산 테스트
  • 허용 오차(TOLERANCE) 값을 여러 개로 바꿔보며 실제 연주에 적합한 기준 탐색
  • 결과 화면(웹페이지) UI를 좀 더 다듬어 발표용으로 정리
02. 진행상황 — 허용 오차 슬라이더

기준값을 직접 탐색할 수 있게 개선

기존에는 허용 오차(TOLERANCE)가 코드에 고정된 값이라, 기준을 바꾸려면 매번 파이썬을 다시 실행해야 했습니다. 이 부분을 결과 화면에서 바로 조정 가능하도록 개선했습니다.

결과 웹페이지에 슬라이더를 추가해서, 슬라이더를 움직이면 그 자리에서 정확도·평균 오차·놓친 음/엉뚱한 음 개수가 즉시 다시 계산되어 화면에 반영됩니다.
03. 구현 방식

파이썬 로직을 웹페이지에도 동일하게 이식

1단계파이썬(accuracy_test.py)의 onset 비교 로직을 자바스크립트로 동일하게 재작성
2단계분석 결과 JSON에 원본 onset 리스트를 그대로 포함시켜, 브라우저에서도 재계산할 수 있는 재료를 전달
3단계슬라이더 값이 바뀔 때마다 자바스크립트가 즉시 재계산하여 화면(정확도, 통계, 그래프)을 갱신
04. 검증

파이썬과 웹페이지 계산 결과 일치 확인

파이썬에서 계산한 정확도와, 자바스크립트로 동일한 조건에서 재계산한 정확도가 정확히 일치하는지 별도로 대조했습니다.

  • 동일한 조건에서 두 계산 결과가 정확도, 평균 오차, 놓친 음·엉뚱한 음 개수까지 완전히 일치
  • 결과가 심어진 리포트 페이지가 정상적으로 생성되고, 슬라이더와 그래프가 페이지 로드와 동시에 문제없이 표시되는 것을 확인
05. 이번 개선의 의미

왜 이 기능이 필요한가

  • 사람마다, 곡마다 "얼마나 엄격하게 채점해야 적절한지"의 기준이 다를 수 있음
  • 슬라이더로 기준을 직접 움직여보며 본인 연주 수준에 맞는 채점 기준을 스스로 찾을 수 있음
  • 발표에서도 기준에 따라 정확도가 어떻게 달라지는지 그 자리에서 바로 보여줄 수 있어 설명력이 좋아짐
06. 다음 계획

다음 주까지 할 일

  • 실제 기타 연주를 스마트폰으로 녹음해서 진짜 데이터로 전체 기능 테스트
  • 슬라이더로 찾은 적절한 허용 오차 기준값을 프로그램 기본값으로 반영
  • 결과 화면 UI 마무리 다듬기 (모바일 화면 대응 등)
